# Database workflow

PostgreSQL 16, Prisma 7 (client generated with driver adapters, no Rust query engine at runtime).

## Conventions

- Every tenant-owned table has `tenant_id uuid not null`, a row-level security policy, and indexes that lead with `tenant_id`.
- References between tenant-owned tables are **tenant-qualified**: add `@@unique([tenantId, id])` to the parent and relate with `fields: [tenantId, parentId], references: [tenantId, id]`. Foreign-key checks bypass RLS, so a plain `parent_id` key would allow cross-tenant references.
- Organisation records are archived (`status`), not deleted; don't grant `DELETE` on them to `app_rw`.
- Primary keys are UUIDv7, generated by the client (`@default(uuid(7))`).
- Timestamps are `timestamptz` in UTC. Business dates use `date`. Timezones are stored as IANA ids (`Asia/Kolkata`).
- Money is `numeric(19,4)` (`@db.Decimal(19, 4)`), never floating point.
- Tables and columns are `snake_case` via `@@map` / `@map`.

## Changing the schema

1. Edit `packages/database/prisma/schema.prisma`.
2. Create the migration without applying it: `pnpm db:migrate:dev --name <what_changed>`.
3. Read the generated SQL. Add RLS policies and grants for any new tenant table in the same or a following hand-written migration.
4. Destructive statements (`DROP`, `TRUNCATE`, column type changes, `DELETE FROM`) need a comment `-- approved-destructive: <reason>` and an explicit reviewer sign-off. `pnpm db:check` enforces the comment.
5. Open a PR. CI applies every migration to an empty database, checks the schema and migrations agree, and runs the isolation tests.
6. After approval, staging and production apply migrations with `prisma migrate deploy` from a one-off ECS task (Phase 22).

## Never

- `prisma db push` or `prisma migrate reset` against any shared database. CI fails if either appears in a script or workflow.
- Editing a migration that has been applied anywhere outside your machine. Write a new one.
- Connecting the API or worker as `app_migrator`.

## Tenant context in code

```ts
import { withTenant } from '@smart-hr/database';

const settings = await withTenant(db, session.tenantId, (tx) => tx.tenantSetting.findMany());
```

`withTenant` validates the id, opens a transaction and sets `app.tenant_id` for that transaction only. Outside it, tenant tables return no rows.
